## Пункт 2. Коды сбавок: переключатель «Активен (используется на пульте)» — область действия и безопасность данных

### Ответы на вопросы (по текущему коду)
1. **Да, влияет на все соревнования.** `deduction_codes` — единый глобальный справочник (правило R-7.8, `docs/JUDGING_RULES.md`; модель `app/Models/DeductionCode.php`). Фильтр `is_active` используется везде, где коды попадают на пульт: `JudgePad` и `SuperJudgePad` (`DeductionCode::active()->ordered()`), а также в PDF «Памятка кодов сбавок» (`app/Http/Controllers/DeductionCodesMemoPdfController.php`). Привязки к конкретному соревнованию у кодов нет.
2. **Прошлые данные не изменятся.** При нажатии кода судьёй в `score_deductions` сохраняется **снимок** `code / label / value` (миграция `2026_09_24_100100_create_deduction_codes_tables.php`, правило R-3.12/R-7.8, модель `ScoreDeduction`). FK `deduction_code_id` — nullable с `nullOnDelete`. Выключение, правка и даже удаление кода не меняют задним числом уже выставленные оценки и прошлые протоколы.
3. **Что делать, если на следующем соревновании нужен другой набор.** Варианты ниже; **решено заказчиком 05.10.2026: вариант A**.

### Варианты (**решено заказчиком 05.10.2026: вариант A**)
- **A (рекомендуемый) — набор кодов per-competition.** Глобальный справочник остаётся «как есть»; у соревнования появляется свой набор активных кодов.
- **B — процедурный.** Без доработок кода: перед турниром админ вручную включает нужные коды и выключает лишние. Нулевые затраты, но глобальный переключатель продолжает «переключать всё».
- **C — пресеты.** Именованные наборы («Кубок 2026», «Чемпионат»), назначаемые соревнованию. Гибко, но самый большой объём.

### Шаги (для варианта A)
1. Миграция: таблица `competition_deduction_codes` (`competition_id`, `deduction_code_id`, `is_active`, `sort_order` — override полей справочника), уникальность пары.
2. Модель `Competition` — relation `deductionCodes()`; метод выборки «эффективного» набора: override соревнования, иначе глобальный `is_active`.
3. `JudgePad` / `SuperJudgePad`: загрузка кодов через эффективный набор текущего соревнования (вместо `DeductionCode::active()`); логика нажатий (`pressCode`, лимиты `MAX_CODE_REPEATS`, снимок в `score_deductions`) не меняется.
4. UI: в карточке соревнования (`CompetitionResource`) — управление набором кодов (чекбокс-список «показывать на пульте» + порядок); глобальный тумблер `is_active` остаётся значением по умолчанию для новых соревнований.
5. PDF «Памятка кодов сбавок» — формировать по эффективному набору соревнования.
6. Проверки: два соревнования с разными наборами → на пульте соответствующие кнопки; выключение кода у нового соревнования не влияет на протоколы старого.

**Реализация (итог):** миграция `competition_deduction_codes (competition_id, deduction_code_id)` — без отдельных колонок `is_active`/`sort_order` (наличие строки = код входит в набор соревнования; порядок наследуется из справочника). Метод эффективного набора — `Competition::padDeductionCodes()` (свой набор, иначе глобальный активный). UI — секция «Коды сбавок (судья A)» в карточке соревнования с чекбокс-списком «Показывать на пульте» (порядок — как в справочнике). PDF «Памятка кодов сбавок» тоже формируется по эффективному набору.
