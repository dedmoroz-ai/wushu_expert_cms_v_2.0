## 2. Состояние соревнования и порядок выступлений

| Код | Правило | Статус | Реализация |
|---|---|---|---|
| R-2.1 | Соревнование имеет статус `competitions.status_code`: `0` — ожидание, `1` — идёт, `2` — пауза, `3` — завершено. | ✅ | `ManageCompetition.php` |
| R-2.2 | Оценки принимаются **только** при статусе `1` («идёт»). В остальных статусах пульты показывают «Турнир не запущен» / «Турнир не активен». | ✅ | `JudgePad::loadState()`, `SuperJudgePad::loadState()` |

| R-2.5 | Статус заявки `registrations.status`: `0` — ожидает, `1` — на ковре, `2` — выступил. При смене участника предыдущему ставится `2`, новому — `1`. | ✅ | `ManageCompetition::changeAthlete()` |
| R-2.6 | При запуске соревнования, если участник на ковре не выбран, автоматически выбирается первый по `sort_order`. | ✅ | `ManageCompetition::start()`, `setFirstAthlete()` |
| R-2.7 | Завершение соревнования (`status_code = 3`) снимает участника с ковра (`current_registration_id = null`). | ✅ | `ManageCompetition::stop()` |
| R-2.8 | Стартовый порядок формируется жеребьёвкой: «вид программы (`styles.sort_order`) → возрастная группа (`age_groups.sort_order`) → случайный порядок внутри группы». Номера `sort_order` присваиваются подряд, начиная с 1. | ✅ | `RegistrationsRelationManager` → «Провести жеребьёвку» |
| R-2.9 | Альтернативный (неслучайный) вариант формирования: «вид → группа → пол → алфавит»; при этом обнуляются `status` и `score`. | ✅ | `CompetitionResource` → действие `generate_protocol` |
| R-2.10 | Одновременно обслуживается **только одно** активное соревнование — все пульты и табло берут первое соревнование с нужным статусом. Параллельные ковры/площадки не поддерживаются. | ⚠️ | см. п. 8.11 |
| R-2.11 | Для каждого соревнования выбирается **сценарий судейства** (`competitions.judging_scheme`): `simple` — «только судьи A» (одна панель, прежний расчёт, по умолчанию) или `ab` — «судьи A / B» (две панели, итог = среднее A + среднее B). Сценарий `abc` (с судьями C — трудность) зарезервирован, см. п. 9.1–9.2. | ✅ | `Competition::judgingScheme()`, `CompetitionResource` (поле «Сценарий судейства») |

| R-4.8 | Отбрасывание крайних оценок выполняется всегда по одной сверху и снизу — независимо от числа судей (3, 5, 7). | ⚠️ | см. п. 8.6 |
| R-4.9 | Результат авторасчёта подставляется в поле «Итоговый балл», но старший судья может **отредактировать его вручную** (до 8 символов). Отображаются два значения: «Итоговый балл» (редактируемый) и «Автоматически» (расчётный). | ✅ | `finalScoreInput`, `calculatedAvg` |
| R-4.10 | Утверждение протокола (кнопка «В ПРОТОКОЛ», с подтверждением) сохраняет `registrations.final_score` и выставляет `is_completed = true`. | ✅ | `SuperJudgePad::finalizeProtocol()` |
| R-4.11 | Итоговый балл проверяется по тому же диапазону, что и оценки судей (0.000–10.000 с лимитами возрастной категории). Значение вне диапазона не сохраняется. | ✅ | `finalizeProtocol()`, `App\Support\ScoreRange` |
| R-4.12 | При вводе итогового балла допускается запятая — она автоматически преобразуется в точку. | ✅ | `ScoreRange::parse()` |
| R-4.13 | После утверждения система переходит к следующему участнику **строго вперёд** — первому по `sort_order` **больше текущего** среди заявок с `is_completed = false`. К пропущенным участникам автоматического возврата нет. | ✅ | `finalizeProtocol()` |
| R-4.14 | Если впереди заявок нет, ковёр освобождается (`current_registration_id = null`). Если при этом остались неоценённые участники позади — выводится предупреждение «Список пройден до конца. ## 8. Расхождения и «серые зоны»

Перечень несогласованностей, обнаруженных в действующем коде. Их желательно
решить до внесения дополнений, так как от них зависит формулировка новых правил.

**8.1. Точность оценок судей. ✅ РЕШЕНО (23.09.2026)**
~~Колонка `scores.score` имеет тип `decimal(4,2)`~~ — приведена к `decimal(5,3)`.
Единая точность 3 знака закреплена в константе `ScoreRange::PRECISION`, ввод на обоих
пультах ограничен 3 знаками после точки и 2 цифрами целой части.
*Реализация:* `database/migrations/2026_09_23_100000_change_scores_score_precision.php`,
`app/Support/ScoreRange.php`, `JudgePad::addNumber()`, `SuperJudgePad::appendDigit()`.

**8.2. Диапазон допустимых оценок не единый. ✅ РЕШЕНО (23.09.2026)**
Задан единый диапазон **0.000–10.000** (`ScoreRange::GLOBAL_MIN` / `GLOBAL_MAX`),
который сужается лимитами возрастной категории (см. 8.3). Проверка выполняется:
- при наборе на клавиатуре (кнопка не принимает недостижимое значение);
- при сохранении оценки линейным судьёй (`JudgePad::submitScore()`);
- при сохранении оценки старшим судьёй (`SuperJudgePad::submitMyScore()`);
- при утверждении итогового балла (`SuperJudgePad::finalizeProtocol()`) — закрывает R-4.11;
- при ручной правке в стартовом протоколе (`RegistrationsRelationManager`).

Линейный судья теперь может выставить `10.000`; ограничение «не ниже 5» снято и
заменено лимитами категории.
*Реализация:* `app/Support/ScoreRange.php` (в т.ч. `isPrefixReachable()` — корректно
разрешает набор «1» как начало «10» даже при минимуме 5).

**8.3. Лимиты баллов по категориям. ✅ РЕШЕНО (23.09.2026)**
Лимиты перенесены из неиспользуемой таблицы `categories` в **`age_groups`**
(поля `min_score` / `max_score`, тип `decimal(5,3)`, `nullable`), так как ограничения
относятся к возрастной категории. Пустое значение = общесистемная граница.
Редактируются в разделе «Справочники → Возрастные группы».
*Реализация:* `database/migrations/2026_09_23_100100_add_score_limits_to_age_groups_table.php`,
`AgeGroup::scoreRange()`, `Registration::scoreRange()`, `AgeGroupResource.php`.
Старая миграция по `categories` сделана безопасной (`Schema::hasTable`).

**8.4. Бригада турнира влияет на расчёт. ✅ РЕШЕНО (23.09.2026)**
Ожидаемое число оценок считается по бригаде, привязанной к соревнованию
(`competition_user`), а не по всем судьям системы. Судьи вне бригады остаются
в системе, но для этого турнира неактивны и в расчёте не участвуют.
Оценка старшего судьи учитывается только если он сам входит в бригаду.
На пульте выводится счётчик «ОЦЕНОК: получено / ожидается» и предупреждение,
если бригада не назначена.
*Реализация:* `Competition::activeJudges()`, `SuperJudgePad::loadState()`.

**8.5. Пульт линейного судьи проверяет допуск. ✅ РЕШЕНО (23.09.2026)**
`JudgePad::mount()` проверяет роль `judge` **и** `is_active_judge` (403 при отказе);
`JudgePad::loadState()` дополнительно проверяет вхождение в бригаду активного
соревнования («Вы не в бригаде этого турнира»). Проверка повторяется
в `submitScore()` на момент записи оценки.
*Реализация:* `JudgePad::mount()`, `JudgePad::loadState()`, `JudgePad::submitScore()`.

**8.6. Система судейства A / B. ✅ РЕШЕНО частично (24.09.2026): сценарии `simple` и `ab`; `abc` — отложен**
*Требование.* Перейти на судейство по панелям A\B, а для нандý — A\B\C; сценарий
выбирается на соревнование. Судьи A ставят сбавки от 5 баллов, лимиты судей B
настраиваются по возрастным категориям.
*Решение.*
- У соревнования поле «Сценарий судейства»: `simple` (прежняя логика, по умолчанию) или `ab` (R-2.11).
- Каждому судье бригады (и старшему судье) назначается функция `A` / `B` (R-3.12, R-4.18).
- Судья A нажимает кнопки кодов из общего справочника, оценка = 5 − сумма сбавок, код — не более 2 раз (R-3.13, R-3.14, R-7.8).
- Судья B вводит 0–5 с лимитами B категории (R-3.15).
- Итог = среднее A + среднее B, в каждой панели — с отбрасыванием крайних при 3+ оценках (R-4.19).
- Для бригад 5 и 7 судей правило отбрасывания прежнее: одна мин. и одна макс. в каждой панели.
*Статус.* `simple` и `ab` — ✅. `abc` (судьи C, трудность) — ❌, отдельный этап (п. 9.1–9.2).
*Реализация:* миграции `2026_09_24_100000…`, `2026_09_24_100100…`, `2026_09_24_100200…`;
`App\Support\JudgingCalculator`, `App\Support\ScoreWriter`, `ScoreRange::forPanel()/forJudge()/totalRange()`,
`JudgePad`, `SuperJudgePad`, `DeductionCodeResource`. Тесты: `tests/Unit/JudgingCalculatorTest.php`,
`tests/Unit/ScoreRangePanelTest.php`, `tests/Feature/AbJudgingFlowTest.php`, `tests/Feature/JudgingRulesTest.php`.

**8.7. Механизм исправления оценки. ✅ РЕШЕНО (23.09.2026)**
Добавлены три пути исправления, все — только до утверждения протокола
(`registrations.is_completed = false`), каждое действие пишется в журнал (8.9):
1. **Линейный судья** — кнопка «Исправить оценку» на своём пульте
   (`JudgePad::startEditing()` / `cancelEditing()`, затем повторный `submitScore()`).
2. **Старший судья** — кнопка «Исправить» на своей карточке (`SuperJudgePad::editMyScore()`).
3. **Старший судья** — кнопка «Снять» на карточке линейного судьи
   (`SuperJudgePad::resetJudgeScore()`), после чего судья выставляет оценку заново.

**8.8. Автопереход двигается только вперёд. ✅ РЕШЕНО (23.09.2026)**
В поиск следующего участника добавлено условие `sort_order > текущего`.
Если впереди никого нет, но остались пропущенные участники позади, система
**не возвращается к ним автоматически**: выводится стойкое предупреждение
«Список пройден до конца. Остались неоценённые участники: N» и предлагается
выбрать их вручную в пульте управления.
*Реализация:* `SuperJudgePad::finalizeProtocol()`.

**8.9. Журнал действий (аудит). ✅ РЕШЕНО (23.09.2026)**
Создана таблица `judging_logs` и модель `JudgingLog`. Фиксируются действия:
`score_created`, `score_updated`, `score_deleted`, `final_score_changed`,
`protocol_finalized`. Для каждой записи хранятся: соревнование, заявка, судья,
**исполнитель** (`actor_id` — может отличаться от судьи), старое и новое значение,
причина и IP-адрес.
Просмотр: раздел «Соревнования → Журнал судейства» (только `admin` / `head_judge`,
режим только чтение, с фильтрами по действию, соревнованию и судье).
При ручной правке итогового балла (на пульте и в стартовом протоколе) можно указать
причину — она попадает в журнал.
*Реализация:* `database/migrations/2026_09_23_100200_create_judging_logs_table.php`,
`app/Models/JudgingLog.php`, `app/Filament/Resources/JudgingLogResource.php`.

**8.10. Нет процедуры протеста/апелляции.**
Пока не делаем.

**8.11. Поддерживается только одно активное соревнование.**
Все пульты и табло используют `->first()` для выборки соревнования — параллельная
работа на нескольких коврах невозможна.
Это не нужно, у нас всегда один ковёр, но возможно когда-нибудь к этому вернёмся.

**8.12. Нет разделения мест при равенстве баллов.**
Участники с одинаковым итоговым баллом делят место (R-6.5); критериев тайбрейка
(сравнение по отброшенным оценкам, по трудности и т.п.) нет.
Оставляем как есть.

**8.13. Оценки на табло анонимны.**
Табло выводит значения оценок в порядке записи в БД, без сопоставления с судьями
(R-5.4), поэтому позиция оценки на экране может меняться между обновлениями.
Это оставляем как есть.
